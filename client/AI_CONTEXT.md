# Client

Vue 3, Vite, and TypeScript Electron renderer. Electron loads the production build from `dist/` with `BrowserWindow.loadFile()`.

## Structure

- `src/windows/window.ts` defines the renderer-window MessagePort bridge and connection-scoped RPC proxy owner, including the shared Command storage proxy used by the Command Page and settings.
- `src/windows/main/main.ts` exports the process-level `gMainApplication`, which owns its `Window`, initializes the bridge, and then mounts the main-window Vue application. Its shared `quit()` flow guards concurrent close and restart requests and runs registered Page close callbacks before calling the corresponding Window RPC.
- `src/windows/main/MainApp.vue` owns the main-window shell, persistent page host, application-level dialog and message hosts, and delegates the tray Close command to the shared application quit flow.
- `src/windows/main/components/MainTitleBar.vue` owns navigation, window controls, optional current-page refresh, Environment, and Help actions, the current-page settings trigger, and the application About action. Optional actions are shown only when the active Page definition provides their contracts. Its close button hides the Window to the system tray. `PageHelpPanel.vue`, `PageSettingsPopover.vue`, and `AboutPanel.vue` cover the full page content area; About displays the build-time application version plus main-provided application and log directories, opens those fixed directories and the fixed GitHub release, issue, discussion, and Ko-fi pages through Window RPC, and edits the persisted automatic-update switch and check delay.
- `src/windows/main/themes/` owns the global theme entry and modular token sets. `dark/` is statically bundled through `themes/mainTheme.css`; configured external themes are resolved by the Theme server object and injected before Vue mounts. The title bar lists available themes and persists live selection. Applying a theme updates its dynamic stylesheet first, then notifies initialized token-backed imperative surfaces such as Monaco and xterm.js on the next animation frame so they read stable computed tokens. Theme-handler registrations have independent lifecycles even when multiple components register the same function reference. A missing configured theme resolves to bundled `dark`. Components consume semantic tokens instead of defining theme-specific literals. The global `--font-family` uses `Consolas`, `Courier New`, and monospace throughout the UI; Monaco and xterm use the same stack through their imperative options. Component corner radii use the theme-level `--radius-small`, `--radius-medium`, and `--radius-large` scale; `0` and `50%` are reserved for explicitly square or circular shapes. The global theme suppresses CSS outlines for all elements, including browser-default and component focus outlines; focus behavior itself remains enabled.
- `src/components/PersistentStack.vue` lazily mounts each keyed view on first activation, then keeps it measurable and mounted while excluding inactive views from interaction and accessibility.
- `src/components/ConfirmDialog.vue` is the single application-level confirmation-dialog host. Callers use the typed `confirmDialog(options)` Promise API instead of mounting dialog instances or maintaining resolver state.
- `src/components/OperationProgressDialog.vue` is the application-level blocking progress-dialog host mounted by `MainApp`. Callers wrap asynchronous work with `runWithOperationProgress()`; the host owns the 300ms delayed reveal, focus isolation and progress presentation.
- `src/components/PopupWindow.vue` provides the shared popup shell, semantic role, centered or externally owned positioning, optional title-bar dragging, edge and corner resizing, viewport constraints, and header, content, and footer slots. Without `dismissDelayMs` it remains visible until its owner closes it. With `dismissDelayMs` it auto-dismisses, optionally fades, and pauses for external state or hover only when the corresponding pause option is enabled. `PopupToast`, `PopupSelect`, and `MacroPopup` reuse this shell while retaining their own content and close decisions; modal consumers such as `ConfirmDialog` retain their own backdrop and focus policy. Every `PopupToast` message is also recorded in `MessageStore` with its supplied level or `info` by default; immediate duplicate records are coalesced by the store.
- `src/components/ContextMenu.vue` accepts an anchor position and allowed area rectangle, then owns body teleportation, final position calculation, boundary clamping, overflow scrolling, and standard action and separator styling. Feature owners provide the anchor, area, menu actions, and close behavior.
- `src/components/SortButton.vue` provides a reusable descending, ascending, and inactive sort cycle for list filters.
- `src/components/FindBar.vue` provides the shared VS Code-style find controls and keyboard behavior. `src/components/textSearch.ts` owns case-sensitive, whole-word, and regular-expression matching for text-backed surfaces.
- `src/components/SplitContainer.vue` accepts one or more direct default-slot items, arranges them horizontally or vertically, and inserts accessible transparent separators with a centered VS Code-style three-dot grip. Adjacent items draw the two visible boundary lines without spacing from the separator by default; layouts that own their pane borders can disable these item borders. The component owns pointer and keyboard resizing, adjacent-item CSS constraints, and temporary document interaction state. Separators always resize adjacent direct items; positioned overlay separators are not supported.
- `src/components/PopupSelect.vue` is the shared application dropdown. Feature views use it instead of native selects or local listbox implementations.
- `src/windows/main/pages/` uses registries for top-level pages and tools. A Page definition may register a `helpComponent`; only those pages receive the title-bar Help action. Views enter the shared persistent stack on first activation and then preserve local state, layout measurements, and scroll position. Global config restores the active top-level Page; an unavailable saved Page resolves to the first registered Page and is persisted. The Tools sidebar follows the shared category order, defaults to its first visible Tool, and persists the active Tool, favorites, and collapsed groups through Config RPC. An unavailable saved Tool resolves to the first visible Tool and is persisted; a failed settings load keeps favorite and collapse controls read-only until an explicit retry succeeds. Standard two-pane Tools use `SplitContainer` for resizable desktop columns and stacked narrow layouts, with pane borders matching the Markdown workspace radius. Shared and Token-specific pane labels use `--tool-pane-header-height`, so labels with actions remain aligned with text-only labels. Markdown owns a dedicated Monaco formatting workspace with Markdown language support, sanitized `markdown-it` preview, source-line-aligned synchronized scrolling, and independently collapsible panes managed by `SplitContainer`. JSON and YAML share a Monaco data editor and a `SplitContainer`-managed resizable input and output layout; JSON uses Monaco language support while YAML content is displayed and edited as plain text. The File Occupancy tool starts cancellable queries through a connection-scoped notifier, polls displayed PID existence once per second without overlapping checks, lists detailed process identities, and offers confirmed process-tree termination from its context menus.
- Page definitions optionally register a close callback. A tray Close request dispatches a renderer Window event to `MainApp`, which restores and focuses the main Window before running the close callbacks so confirmation dialogs remain visible.
- [`src/windows/main/pages/command/`](src/windows/main/pages/command/AI_CONTEXT.md) owns Command TreeView composition, editor drafts, Macro scope caching, persistence, and dirty-leave confirmation.
- [`src/windows/main/pages/taskCenter/`](src/windows/main/pages/taskCenter/AI_CONTEXT.md) owns the top-level Task Center page.
- [`src/messages/`](src/messages/AI_CONTEXT.md) owns browser-local notifications.
- [`src/components/treeView/`](src/components/treeView/AI_CONTEXT.md) owns the reusable TreeView state model, controller, operations, overlay slots, Explorer, tabs, and layout.
- [`src/components/textEdit/`](src/components/textEdit/AI_CONTEXT.md) owns the reusable Macro parameter and optional multiline text editor.
- [`src/components/terminal/`](src/components/terminal/AI_CONTEXT.md) owns the lazy xterm.js surface and its per-PTY proxy, created through the Window's cached Terminal Service proxy.
- [`src/bridge/`](src/bridge/AI_CONTEXT.md) owns the renderer connection and semantic RPC boundaries.

## Boundaries

- Vue features use cached domain `RemoteObject` proxies; only bridge factories call `BridgeRouter.createRemoteObj`.
- RPC interfaces and task models come from their owning domains under `common/`.
- User-controlled content is rendered as text or sanitized before HTML rendering.
- Global listeners are removed during close or unmount.
- About's Update row sits below Check delay, starts manual updates through the cached Update RPC proxy, and reads status immediately on mount and every second without overlapping polls. A persistent status line below the button replaces its native title tooltip. `CHECKED` allows another check; `UPDATING` disables the action; `NEED_RESTART` offers Restart through the shared application quit flow so Page callbacks can cancel it. A pending restart disables the button and polling. Unknown or unreadable state also disables the action. Manual update and restart submissions invalidate older poll responses, and unmount clears polling and ignores pending responses.
- Router history uses hashes because renderer navigation runs under the `file:` protocol.

## Validation

- `npm --prefix client run typecheck` runs `vue-tsc --noEmit`.
- `npm --prefix client run build` type-checks and builds `client/dist/`.
