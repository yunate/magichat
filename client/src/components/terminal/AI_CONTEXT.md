# Terminal Component

Reusable xterm.js surface backed by one main-side PTY runtime.

## Structure

- `Terminal.vue` owns xterm.js, FitAddon, buffer-to-text search mapping, resize observation, live synchronization from theme-specific terminal CSS tokens, the instance FIFO queue, shared `FunnelTask`-based running checks, and lazy RPC initialization. After replacing the xterm base theme, it reapplies active application-defined OSC color overrides so theme changes do not discard a TUI's runtime palette. Runtime and operation failures are emitted to the business owner and are not rendered inside the Terminal surface. Successful PTY lifecycle and command operations emit concise status messages for the owner to present.
- `terminalClientRpcObject.ts` routes main-side output and stable runtime errors to the owning component.
- `terminalOscColorOverrides.ts` observes complete OSC 4, 10, 11, and 12 commands through xterm's parser without intercepting built-in handling, tracks their 104 and 110-112 resets, and replays active overrides after a base-theme change.
- `terminalTypes.ts` defines the API exposed to business callers.

## Boundaries

- Mounting does not initialize xterm.js or create a PTY. `initialize()` idempotently initializes xterm.js with stdin disabled and creates the RPC runtime and notifier connection, while `createPty()` explicitly starts the requested shell. Callers await `initialize()` instead of mirroring completion through a ready event.
- The component contains no business toolbar, dialogs, or Tab visibility logic. Command owns those interactions, while the shared persistent stack keeps mounted Terminal surfaces measurable. `createPty()` accepts the heartbeat interval and running-status callback as separate optional parameters. Only a positive interval enables Terminal-owned idle-prompt heartbeat checks; non-positive values and `undefined` create no heartbeat timer. The callback may remain enabled independently for event-funnel status updates.
- OSC hyperlinks use the shared asynchronous confirmation dialog and the existing Window `openExternalUrl()` RPC, which accepts only HTTPS URLs without credentials. They do not use xterm's native `confirm()` and `window.open()` path, because native confirmation can disrupt renderer input focus and application windows deny popup navigation. Link-opening errors use the component's existing error event.
- Main output callbacks write directly to xterm.js and do not enter the operation queue. PTY creation registers xterm input and parsed-output subscriptions, while PTY destruction disposes them together with running-status timers and state. An unexpected PTY runtime exit performs the same client-state cleanup, disables stdin, reports a final stopped status when needed, and preserves xterm output for diagnosis. Component unmount destroys the PTY before disposing its remote runtime. Public operations and internal resize/dispose are ordered per component instance.
- `getCurrentLine()` reads the current cursor line from xterm's active buffer and joins wrapped screen rows into one logical line. `isTerminalRunning()` centralizes the component's prompt-based heuristic for callers that need the same observed state; neither API reports actual foreground process state.
- `createPty()` receives the shell type and dimensions as one atomic operation. Main returns the actual Windows PTY backend and OS build so xterm applies the matching resize and reflow behavior; debug sessions use WinPTY because ConPTY can deadlock while the inspector is attached. Optional heartbeat checks start after PTY creation, treat a standard CMD or PowerShell prompt as idle and every other current logical line as running, notify only when the observed state changes, and stop with PTY destruction or component unmount. When either heartbeat or callback checking is enabled, xterm input and server output share a 30ms status-check funnel; additional events within that window do not schedule or delay another check. It therefore covers helper runs and manually entered commands without restarting the heartbeat timer. Business callers own the stop and PTY creation sequence.
- `run()` requires an active PTY and delegates every script type, including PowerShell, to the main-side temporary-script execution path. It never creates a PTY and resolves after the server accepts and writes the invocation. Running status is observed separately from the visible last line.
- Ctrl+A selects from the first non-empty xterm buffer row through the final text cell without highlighting unused viewport rows or sending the control character to the PTY. Ctrl+V always reads text from the system clipboard and pastes it through xterm instead of sending the Ctrl+V control character to the PTY. Ctrl+C copies the current xterm selection and shows a success toast. Without a selection, Ctrl+C remains PTY input so it can interrupt the foreground command.
- Local file dragging is accepted whenever the PTY is active without inspecting the current line. After drop, the Terminal operation queue checks that the PTY is still active and the current logical line is an idle CMD or PowerShell prompt immediately before writing; stale or running states are silently ignored. Raw paths are joined with spaces without shell quoting or escaping, and no Enter key is written. The preload supplies only Electron's `File`-to-path conversion.
- Ctrl+F opens the shared FindBar without sending input to the PTY. The shared text matcher searches each logical xterm line, while Terminal maps string offsets back to buffer coordinates and selects the match nearest the visible cursor or viewport center. Enter and Shift+Enter directly select the next or previous stored buffer position, including wrapped rows, while Escape closes search and restores Terminal focus. Search results are capped at 1000, and the inactive selection theme keeps the active match visible while the search input has focus.
- The Terminal hides xterm's internal scrollbar and owns a compact scrollbar synchronized through xterm's public buffer and scrolling APIs. Its arrows, track paging, and draggable thumb appear only while the buffer contains scrollback content. The first transition to scrollable content measures the track after Vue's next DOM update because `v-show` keeps the track at zero height until it is rendered.
- `stop()` sends Ctrl+C without inferring or waiting for shell state. `destroyPty()` closes the shell process and fully disposes the xterm instance, FitAddon, observers, subscriptions, OSC tracking, search state, and scrollbar state while retaining the remote runtime proxy for reuse. Creating the next PTY rebuilds and focuses a fresh xterm display layer. `clear()` first asks the runtime to clear its PTY buffer representation, then clears the local xterm buffer, search state, and scrollbar state without writing shell input, and returns keyboard focus to xterm. Unmount disposes the remote runtime before destroying its proxy.
