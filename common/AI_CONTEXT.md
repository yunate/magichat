# Common

Shared TypeScript imported by Renderer, Main, Backend and Broker. This layer owns cross-process types, runtime validation, serialization, RPC contracts, and the MessagePort bridge.

## Modules

- `backend/backendRpcApi.ts` defines the PID handshake and Main-only Backend initialization, prepared-restart path and shutdown contracts. Backend hosts all application backend business domains.
- `platform/platformRpcApi.ts` defines restricted Backend-to-Main resource-reveal and shortcut icon capabilities. Renderer peers cannot create this object.
- [`validator.ts`](validator.ts) provides assertion-based runtime narrowing for untrusted values.
- [`serializer.ts`](serializer.ts) defines `ISerializer<T>` and serializer value inference.
- `applicationPaths.ts` owns shared `ApplicationPathsOptions` and its serializer. Main supplies authoritative application/profile, desktop, AppData and executable paths to Backend; Backend passes the same options to Broker. Child processes do not infer UI-host paths from their own executable identity.
- `taskQueue.ts` owns the pure Promise-aware serialized queue shared by Renderer TreeView and Backend/Broker PTY pools. It has no Node or Electron imports.
- [`macroParser.ts`](macroParser.ts) owns the `mh{key}` syntax, extracts references and unique keys, and formats references. It trims whitespace inside braces; keys start with a letter or underscore and may contain non-empty dot- or dash-separated letter, number, and underscore segments. Its strict replacement resolves parameter dependencies and rejects invalid parameters, unknown references, and cycles.
- [`funnelTask.ts`](funnelTask.ts) schedules at most one callback per fixed delay window. Callers may cancel the pending callback or execute it immediately; later schedule requests do not extend an active window.
- [`sleep.ts`](sleep.ts) provides `sleep(milliseconds): Promise<void>` through the environment's global timer, shared by browser renderers and Node-side code without Node-specific imports.
- [`config/`](config) owns shared configuration types. Main-window dimensions, the selected application theme, and the active top-level Page form one strict `global` config. Tools config stores the active Tool, favorites, and collapsed groups. Their serializers accept the immediately preceding schema without the active selection field and supply a migration value; Client resolves unavailable selections against its current registries and persists the result. Command config stores Terminal placement, its initial path, and storage Roots; the immediately preceding schema without the Terminal initial path receives the current default during strict read. Task Center config stores queue concurrency plus template storage Roots and accepts the immediately preceding max-parallel-only schema. Update config controls automatic startup checks and a `random` or `1–3600` second delay, defaulting to enabled with a random delay. The module also owns the config key-to-serializer registry and client-to-server Config RPC interface.
- [`command/`](command/AI_CONTEXT.md) owns Command folder and script item data, strict serializers, and the Command TreeView DataProvider RPC interface.
- [`tasks/`](tasks/AI_CONTEXT.md) owns task entities, task-specific definitions, model serializers, the client-to-server Tasks RPC interface, and the server-to-client TaskEvents RPC interface.
- [`treeView/`](treeView/AI_CONTEXT.md) owns generic TreeView models, Folder and Item snapshot queries and mutations, strict base serializers, absolute storage-path validation, and DataProvider/DataNotifier RPC contracts.
- `terminal/` owns Terminal shell and creation types, `TerminalRuntimeServiceApi`, and the shared method-only `PtyApi` implemented by `RpcPty`. `getInfo()` is the sole metadata method and returns `TerminalPtyState`, which defines backend and Windows build metadata together with stable terminal identity and live process state. `PtyCallbackApi.onData/onExit` is the single callback contract for local PTYs and renderer notifications; Service `create()` accepts that same callback by reference. Exit callbacks carry complete `TerminalPtyExit` data, and the renderer owns any user-facing exit error message. Callback methods may be local synchronous functions or asynchronous functions; the callback contract does not imply remote ownership. Callbacks are fixed at creation rather than replaceable through the PTY API. Service `create()` returns a callable PTY object by reference, and `destroy(terminalId)` owns PTY and business-resource cleanup.
- `terminal/terminalRunRequest.ts` owns `TerminalRunRequest` and its serializer. It allows extra fields while validating required fields, UUID v4 script identity, absolute normalized Command paths, supported script types, and the script-content length limit. Backend `run` and CLI `prepareRun` share that serializer before creating temporary scripts.
- `terminal/terminalPtyOptions.ts` owns `TerminalPtyOptions`, `TerminalDimensions`, and their strict serializers. Creation options include the required boolean `isUAC`, whose authoritative default is `false`; Backend's PTY Factory uses this shared type directly. Backend validates creation schema and field types through `terminalPtyOptionsSerializer`; Client applies `terminalDimensionsSerializer` for safe-integer columns `1-1000` and rows `1-500`. Path resolution and directory preparation remain Factory behavior rather than serializer side effects.
- `theme/` owns safe theme-folder naming, the built-in default name, resolved theme data, and the client-to-server Theme RPC interface for listing and resolving themes.
- `update/` owns the four-state `UpdateState` enum and `UpdateServerRpcApi`. `CHECKED` means a completed check found no available update and allows another check. `startUpdate()` triggers the update without waiting for completion; `getState()` supplies the authoritative state for renderer polling.
- `window/` owns client-to-main window controls, including hide-to-tray, prepared-update restart, fixed application- and log-directory reveal, fixed release, issue, discussion, and Ko-fi page links, and validated external HTTPS link opening, plus the main-to-client close-request event contract. Restart accepts no executable path from the renderer.
- [`ipc_bridge/`](ipc_bridge/AI_CONTEXT.md) owns MessagePort and local named-pipe transport adapters, peers, and typed RPC routing.
- `uac/` owns the Backend-to-UAC-Broker lifecycle RPC interface. Its `init(ApplicationPathsOptions)` validates and initializes the Broker's application-path singleton during connection setup. CLI environments derive their paths from that singleton without separate initialization. `getUacTerminalRuntimeService()` returns the existing Broker-side `TerminalRuntimeServiceApi` object by reference, without a separate terminal RPC registration or proxy factory.
- `fileOccupancy/` owns process details, query and termination results, the Renderer-to-Backend API, and the separate bidirectional Main-to-UAC-Broker capability API. Both server APIs accept their Client notifier objects directly in `init()`; the bridge passes those objects by reference without temporary factory names. Queries start immediately and deliver completion through client notifier interfaces, so long-running native inspection does not depend on Bridge RPC timeouts.
- `cli/` owns the length-prefixed binary request and response codec used between CLI Helper and the Backend process named-pipe bridge. An `MHC3` request carries every inherited environment variable whose key starts with `MAGICHAT_CLI`, followed by the CLI arguments, as length-prefixed UTF-8 strings under a shared 64 KiB byte limit. Backend injects the complete instance-specific pipe path through `MAGICHAT_CLI_PIPE`; each MagicHat PTY also receives its own `MAGICHAT_CLI_TERMINAL_ID`, while Command runners scope `MAGICHAT_CLI_COMMAND_PATH` to the executing logical Item. The native CLI does not derive or discover these values.

## Boundaries

- Serializers allow undeclared extra fields at the top level and in nested records. Required fields, known-field types, enums, ranges, and business invariants remain validated. Validation does not strip extra fields; explicit domain projections may select only their declared fields. Existing legacy-schema migration recognition is unchanged.
- RPC API names use `Domain + Provider + RpcApi`; `Server` means client-to-server and `Client` means server-to-client.
- RPC interfaces contain method contracts only. Their runtime registerName equals the interface name and is encapsulated by bridge create/register boundaries.
- Business values are validated where untrusted remote-object arguments or results enter a process.
- Task entity serializers are consumed directly; only configuration serializers use dynamic key lookup.
- The public `Spectial` spelling is retained for compatibility.
