# TreeView Contracts

Generic TreeView models, serializers, absolute storage-path validation, and object RPC contracts shared by renderer and main.

## Boundaries

- Workspace, Folder, and Item snapshots contain only TreeView-owned structural metadata. Business `data` is excluded from structural loads.
- Folder and item IDs are UUID v4 values generated by the main-side DataProvider.
- During renderer indexing, a later Folder or Item that duplicates an already indexed same-kind ID receives a new UUID and asks the DataProvider to persist it.
- Tabs persist both the stable entity ID and normalized absolute path. Tabs remain available independently of the currently loaded Explorer tree; an active Tab resolves its entity directly by path and shows an unavailable state when kind, path, ID, or storage is invalid. `activeTabId` references an open tab, while nullable `previewTabId` persists the single unpinned temporary Tab across restarts.
- Workspace, Folder, and Item create operations persist `null` as the explicit uninitialized JSON business-data state and do not accept business data. Entity-data methods transport that nullable JSON string together with ordered opaque extension entries. Business clients own defaults, serialization, validation, and preservation of extensions they do not modify.
- `TreeViewDataProvider` is called by the renderer. Clone and delete receive a renderer-generated operation UUID and return as soon as Main accepts the queued operation; final success or failure is delivered through `TreeViewDataNotifierClientRpcApi.operationCompleted()`. The notifier is also called by Main for external storage changes and non-fatal storage warnings.
- `TreeViewDataProvider.getFolder(path, depth?)` returns the complete recursive subtree when depth is omitted and limits enumeration to the requested positive depth otherwise. `getFolderProperties()` exposes only Folder metadata.
- Workspace rename accepts a validated new name; the main-side provider derives the sibling target path from the normalized source Workspace path.
- `TreeViewStorageRoot` identifies each business-provided root by a display key and absolute path. `TreeViewWorkspaceRef` preserves that root identity when Workspace names overlap.
- Workspace and folder paths are normalized absolute paths. Item paths are normalized absolute `.mh` file paths. `.mh` files contain a leading strict JSON document and zero or more standalone `---MH:<key>---` extension sections.
- The renderer passes explicit normalized absolute paths on every storage operation. Storage-root selection and business storage actions remain outside the generic DataProvider contract.
