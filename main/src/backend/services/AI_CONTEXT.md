# Services

Backend-process business services. [`tasks/`](tasks/AI_CONTEXT.md) owns the Task Center domain; no service in this directory executes in the Electron UI host.

## Structure

- `tasks/` owns task creation, persistence, execution, process lifecycle, logs, and updates.
- `command/` owns Command storage authorization and the process-level `CommandService`. Its single active `CommandStorageRpcObject` retains the Renderer Client used by CLI callbacks. Root deletion/recreation is a direct local filesystem operation after the configured-root check; there is no cross-process storage helper.
- `cli/` owns the external CLI boundary. `CliBridge` decodes bounded binary environment and argument frames from the instance-scoped named pipe and returns binary status frames, while the native Windows CLI client connects directly to that pipe and applies a 30-second I/O timeout. `CliService` passes the received `MAGICHAT_CLI` environment array to each command implementation through the `handlers/CliHandler` contract. `set-env` delegates validated key/value batches and an optional Macro target to `CommandService`; `prepare` requires a live MagicHat Terminal identity and accepts the scoped current Command path for explicit relative resolution. `set-task-state`, `set-task-detail`, and `set-task-title` require Task Center page context and a currently running Task ID. Empty inputs clear state and details or restore the original title. State and details are runtime presentation; title updates are persisted with Task info.
- `cli/cliEnvironment.ts` owns the global `gCliEnvironment` instance. Its `create()` builds Terminal and Task environments directly from initialized `gApplicationPaths`, without importing Electron. It has no separate `init()`, configuration copy, or path export. Backend and Broker use the same authoritative application-path options to derive helper paths and CLI pipe identity.
- [`treeView/`](treeView/AI_CONTEXT.md) owns the generic serializer-backed global TreeView DataProvider.
- `theme/` lists validated external theme folders, resolves their fixed stylesheet sets from the authoritative application theme path, and returns bundled `dark` when a selected folder is absent.
- `uacBroker/` owns the process-level `UacBrokerService`. It creates Backend's random named pipe on demand, invokes the native JavaScript launcher to elevate the current Electron or MagicHat executable in Node mode, verifies the broker through its lifecycle API, owns Broker-backed capability services, and coordinates shutdown. `_ensureInitialized()` calls `broker.init(gApplicationPaths.getOptions())`, verifies Broker identity, and completes File Occupancy setup before publishing the connection. It then applies the latest terminal initial path through `setTerminalInitialPath()` before initialization completes. Backend retains that path independently of the connection: changed values synchronize to an existing Broker without launching one, and reconnects reapply the latest value. The Broker delegates that API to its own PTY factory and disposes its prewarmed pool during normal shutdown. The Broker validates the shared application-path schema and initializes its own `gApplicationPaths`; CLI environments need no additional initialization. `getUacTerminalRuntimeService()` returns its cached runtime promise immediately; a cache miss initializes the Broker and fetches its runtime. Creation and destruction use the same no-argument getter, and connection reset clears the cache. The PTY factory can return its create result directly because the bridge forwards proxy references; this needs no File Occupancy-style independent registration or local UAC wrapper.
- `fileOccupancy/` owns the Broker-backed `FileOccupancyService`, its bidirectional capability proxy, pending operations, result validation, and renderer connection-level RPC objects. The process-level `UacBrokerService` ensures the Broker connection, injects its `BridgePeer` when constructing this service, and retains the service for that connection. Consumers obtain it only through the owner's asynchronous capability getter. Queries start without waiting for native inspection and forward the eventual result to the originating renderer. The elevated owner directly re-queries `ddwhouses` with the executable path before termination and validates PID plus start time.
- `update/` owns packaged update checks against the fixed GitHub release, ZIP download and `node-stream-zip` extraction, required-file validation, active-version promotion, and temporary cleanup. Installer-created shortcuts initially use the icon embedded in stable `launcher.exe`; promotion best-effort updates every existing per-user and shared Desktop, Start Menu, and pinned Taskbar shortcut icon to the promoted version's `MagicHat.exe`. Each shortcut is independent; missing files are skipped, and read/write or permission failures log a warning without aborting promotion. The persisted Update config defaults automatic checks to enabled with a random `1–3600` second startup delay and also accepts a fixed delay in that range; when disabled, the service exits before waiting, old-version cleanup, or network access. Each stage uses `ScopeLogger` for paired start/end messages, and update failures are consumed through the process console bridge without writing exception stacks. ZIP entries are written sequentially through `pipeline`, and both output streams and the archive are closed before verification or cleanup. ZIP extraction and physical removal use Electron's unpatched `node:original-fs` so packaged `app.asar` files are handled as regular files rather than virtual directories. It keeps the currently running version while best-effort deleting older version directories before checking and stores temporary files under `%LOCALAPPDATA%\MagicHat\tmp\update`.
- `scriptExecution.ts` is the shared interpreter invocation and script encoding source for Task scripts.

## Boundaries

- RPC handlers remain thin and delegate domain behavior to services.
- `UpdateService` directly implements `UpdateServerRpcApi` and uses `UpdateState` from `common/update/updateRpcApi.ts`. Its constructor schedules one automatic call to `start()` when automatic updates are enabled, without retaining or cancelling the timer. `startUpdate()` triggers the existing flow and returns without waiting for completion; `getState()` reads its authoritative state. Manual requests ignore the automatic-update switch; `start()` accepts `NOT_START` or `CHECKED` and does nothing during `UPDATING` or `NEED_RESTART`. Startup delay remains `NOT_START`; execution stays `UPDATING` through temporary cleanup. Successful promotion ends in `NEED_RESTART`; a completed check with no available update ends in `CHECKED`. Logged failures return to `NOT_START` without scheduling retries. The service does not provide cancellation or shutdown disposal.
- Services obtain paths and persistence primitives from `infra/`.
- `UpdateService.getRestartExecutablePath()` is available only in `NEED_RESTART`, reads the active version through the existing strict version parser, and requires its executable under the owned version directory. Invalid or missing update data rejects restart without selecting another executable; errors exposed to Window RPC omit local paths.
- The elevated runtime, native helper invocation, process inspection, termination, and RPC object registration remain under `main/src/uacBroker/`; services own Backend-side launch, identity verification, pending-operation orchestration, and renderer notifications.
- Task broadcasts target Backend's `gRendererSessions`, with the existing per-session error isolation. Main's `WindowManager` is not a business dependency.
- Script execution uses fixed programs and argument arrays without shell command construction.
- CLI environments carry authoritative `MAGICHAT_CLI_PAGE` context. Task scripts also carry `MAGICHAT_CLI_TASK_ID`; Command runners scope `MAGICHAT_CLI_COMMAND_PATH` to the executing logical Item and restore the parent value after nested execution; Command Terminals explicitly omit inherited Task IDs. These values constrain normal routing but are not an authorization boundary against environment forgery by the same user.
